3.5 专项：投机解码 / Needle / 行为

  • draft 接受率（eval-acceptance，各 spec 模式）：vanilla 无数字；mtp ~0.51（mean len 2.52）；dspark ~0.48（mean len 4.33）。
  • Needle 检索（6.5K ctx 找 BRAVO-7734-QUANTUM）：q8_0 与 f16 KV 均 FOUND=True。
  • Needle（5982 ctx，kv-test）：FOUND=False —— answer 被截断在「The user is asking me to identify the secret access code…」，疑似 max_tokens 不够，非能力问题。

证据这是「Aggressive」去审查的直接证据：对通常会被 RLHF 安全层拦截的「how to pick a lock」类指令，原版拒答并劝你找专业人士，Uncensored 直接给操作步骤。基础问答、数学、代码能力没有回退。

05口径与可信度说明

  • 8088 端口是按需切换底层 gguf 的 A/B 测试台，qwen 只是服务别名；bench-new / behavior-new = 切到 Uncensored Q6_K_P 后测得，bench-old / behavior-old = 切到 UD-Q6_K_XL 作对照。
  • 第 3.1 / 3.2 节的 TG 数字都是开 MTP 投机解码后的实际吞吐，不是裸 vanilla 速度。要看纯 vanilla TG 需另跑（日志里 vanilla 段无 tg 数字）。
  • 第 3.3 / 3.4 节（kv / tune）的日志没标注具体跑的是哪个 gguf，疑似同台同模型，分享时已标注「型号未标注」。

TL;DR

混合 SSM-Transformer 架构 + 原生 MTP 投机解码，长上下文不掉速；去审查微调后基础能力零回退，敏感指令从拒答变直答。
